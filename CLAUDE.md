# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

`video-meetings` is a pnpm monorepo with two apps:

| Path       | Stack            | Purpose                           |
| ---------- | ---------------- | --------------------------------- |
| `apps/web` | Next.js + HeroUI | Web client                        |
| `apps/api` | NestJS           | Backend API (Prisma + PostgreSQL) |

App-specific guidance lives in `apps/web/CLAUDE.md` and `apps/api/CLAUDE.md`. Read the one for the app you are changing before editing it.

## Commands

Run from the repo root:

- `pnpm install` - install all workspace dependencies (its `prepare` script installs the Husky git hooks)
- `pnpm dev` - run web and api together
- `pnpm dev:web` / `pnpm dev:api` - run one app
- `pnpm build` - build every app
- `pnpm lint` - lint every app
- `pnpm test` - run tests in every app that has them
- `pnpm format` / `pnpm format:check` - Prettier write / check
- `docker compose up -d postgres` - start PostgreSQL 17 from `docker-compose.yml` (defaults: user/password `postgres`, db `video_meetings`, port `5432`; override via `POSTGRES_*` env vars)
- `pnpm --filter api db:migrate` - create and apply a Prisma migration in development (`db:deploy` applies existing migrations only)

Use `pnpm --filter <app> <script>` to target a single app (`web` or `api`).

## Tooling and conventions

- Package manager is **pnpm** (`packageManager` pins `pnpm@11.17.0`). Do not use npm or yarn; do not add a second lockfile.
- Node **22+** (`.nvmrc` is `22`).
- Workspace packages are declared in `pnpm-workspace.yaml` as `apps/*`.
- Formatting: Prettier with `singleQuote: true` and `trailingComma: "all"`. `.editorconfig` sets LF line endings, 2-space indentation, UTF-8, and a final newline. Run `pnpm format` before finishing a change.
- Transcription of uploaded mp3/mp4 files runs a local Whisper (`pip install -U openai-whisper`) and needs `ffmpeg` on `PATH`; `WHISPER_MODEL` defaults to `tiny`. Details in `apps/api/CLAUDE.md`.
- `.env*` files are git-ignored (except `.env.example`). Never commit secrets or `.env` contents.
- Generated output (`dist/`, `.next/`, `*.tsbuildinfo`, `next-env.d.ts`) is git-ignored. Do not edit it by hand.
- Git hooks use **Husky** (v9, root devDependency). `.husky/pre-commit` runs `pnpm lint && pnpm test && pnpm --filter api test:e2e` on every commit. The hook is installed by the root `prepare` script (`git config core.hooksPath .husky/_`). Do not skip it with `--no-verify`; fix the failure instead.
- The e2e step needs PostgreSQL running and migrated before every commit. Run `docker compose up -d postgres` and then `pnpm --filter api db:deploy`. If the database is not reachable, the commit fails at the e2e step.

## Working in this repo

- Keep changes scoped to the app they belong to. Shared tooling changes belong at the root.
- Run the relevant app's `lint` and `test` after a change. Report any failures with their output rather than assuming success.
- This directory is not currently a git repository. Do not run `git` commands expecting history, and do not commit unless asked.

## Documentation

- When a change alters the project's architecture, update the documentation in the same change. Architecture changes include: adding, removing, or renaming an app, package, or top-level module; changing the stack, framework, or major library; changing how the apps communicate (API routes, shared types, env variables, ports); changing the build, dev, test, or lint setup; and changing the directory layout or key conventions.
- Keep these files in sync with the code:
  - `CLAUDE.md` (root): the project table, commands, and conventions.
  - `README.md` (root): the app table, dev commands, and quick-start steps.
  - `apps/<app>/CLAUDE.md`: the app's stack, entry points, commands, and conventions.
  - `apps/<app>/README.md`: the app's setup and run instructions.
- Do not edit `apps/web/AGENTS.md`. It is generated by `next dev`.
- If a change affects architecture and you cannot update the docs, say so in your final message and list what is out of date.

## Token efficiency

- `git diff` всегда с `--unified=0`
- `git log` всегда с `--oneline -10`
- `gh issue list` всегда с `--json number,title`
- `npm run test` всегда с `--silent`
- `npx tsc --noEmit` всегда с `2>&1 | tail -5`

## Именование

- Файлы: feature.type.ts (meetings.service.ts)
- Методы описывают действие: createMeetingWithFiles
- Переменные по смыслу: meetingId не id, x, data
- Enum вместо строк: MeetingStatus.PENDING не 'pnd'
- Константы вместо magic numbers: MAX_FILE_SIZE_MB

## Размер

- Файл > 200 строк -> декомпозируй перед добавлением кода
- Метод > 30 строк -> выдели в приватный метод
- Вложенность > 3 уровней -> рефакторить

## Зависимости

- Импортируй через модуль, не через сервис напрямую
- Никаких circular dependencies — проверяй перед коммитом
- Shared типы только из @app/shared/types

## Рефакторинг

- Перед добавлением кода в большой файл — декомпозируй
- Тесты зелёные на каждом шаге рефакторинга
