# PRD: Профиль пользователя и его редактирование

**Дата**: 2026-11-18
**Статус**: Draft

## Цель

Дать пользователю страницу профиля и страницу редактирования, где можно задать имя, загрузить аватар и сменить пароль. Аватар и имя видны в профиле и в шапке главной страницы, чтобы пользователь видел, под какой учётной записью он вошёл.

## Пользовательские сценарии

- Авторизованный пользователь открывает страницу профиля -> видит аватар (или инициалы, если аватара нет), имя (или email, если имя не задано) и email.
- Пользователь открывает страницу редактирования и меняет имя -> после сохранения новое имя показано в профиле и в шапке.
- Пользователь выбирает файл JPG/PNG/WebP до 2 МБ -> после сохранения новый аватар показан в профиле и в шапке.
- Пользователь выбирает файл неподходящего формата или больше 2 МБ -> видит сообщение об ошибке, аватар не меняется.
- Пользователь удаляет аватар -> в профиле и шапке показываются инициалы.
- Пользователь вводит старый пароль и новый пароль -> пароль меняется, пользователь остаётся залогиненным, другие токены не отзываются.
- Пользователь вводит неверный старый пароль -> видит ошибку, пароль не меняется.
- Неавторизованный пользователь открывает страницу профиля или редактирования -> перенаправляется на вход.

## В скоупе

- Страница профиля: аватар, имя, email.
- Страница редактирования профиля с тремя независимыми действиями: смена имени, смена/удаление аватара, смена пароля.
- Новое необязательное поле «имя» у пользователя. Пока оно не задано, везде показывается email.
- Аватар: форматы JPG, PNG, WebP, максимум 2 МБ, без обрезки в интерфейсе; можно заменить и удалить.
- Заглушка с инициалами, когда аватара нет.
- Отображение аватара и имени на странице профиля и в шапке главной страницы (блок «кто залогинен»).
- Смена пароля по старому паролю. Требования к новому паролю те же, что при регистрации (минимум 8 символов); новый пароль не должен совпадать со старым.
- Ссылка на профиль из шапки.
- Сообщения об ошибках и успехе для каждого действия.

## Не в скоупе

- Смена email.
- Уникальность имени (имена могут повторяться).
- Обрезка и редактирование изображения до загрузки.
- Отзыв других сессий и токенов при смене пароля.
- Восстановление пароля по почте.
- Показ аватара в списке участников встречи и в других местах, кроме профиля и шапки.
- Профиль других пользователей, публичные страницы профилей.
- Удаление аккаунта.

## Технические ограничения

- Сейчас у `User` есть только `email` и `passwordHash`; нужны новое поле имени и ссылка на аватар, то есть миграция Prisma.
- Правила пароля при регистрации: `MinLength(8)` (`apps/api/src/auth/dto/credentials.dto.ts`); новая валидация не должна им противоречить.
- Файлы аватаров хранятся на диске так же, как файлы встреч (multer, `diskStorage`); для них нужна своя директория и настройка в env.
- Файл аватара должен быть доступен залогиненному клиенту для отображения; при замене и удалении старый файл с диска удаляется.
- Формат и размер файла проверяются на сервере, а не только в браузере.
- Изменения затрагивают и `apps/api`, и `apps/web`; при добавлении модуля, эндпоинтов и env-переменных нужно обновить `CLAUDE.md` и `README.md` соответствующих приложений.

## Критерии готовности

- [ ] Страница профиля доступна только авторизованному пользователю; неавторизованный перенаправляется на вход.
- [ ] Профиль показывает аватар или инициалы, имя (или email, если имя пусто) и email.
- [ ] Пользователь может задать и изменить имя; изменение видно в профиле и в шапке без повторного входа.
- [ ] Пустое имя при сохранении сбрасывает его, и везде снова показывается email.
- [ ] Загрузка JPG, PNG и WebP до 2 МБ проходит успешно; аватар виден в профиле и в шапке главной.
- [ ] Файл другого формата или больше 2 МБ отклоняется сервером с понятной ошибкой; текущий аватар не меняется.
- [ ] Пользователь может удалить аватар; в профиле и шапке показываются инициалы, файл удалён с диска.
- [ ] При замене аватара старый файл удаляется с диска.
- [ ] Смена пароля требует верный старый пароль; при неверном старом пароле возвращается ошибка и пароль не меняется.
- [ ] Новый пароль короче 8 символов или совпадающий со старым отклоняется с понятной ошибкой.
- [ ] После смены пароля пользователь остаётся залогиненным, вход со старым паролем невозможен, с новым возможен.
- [ ] Пользователь не может изменить профиль или пароль другого пользователя.
- [ ] Для новых эндпоинтов есть unit- и e2e-тесты, для страниц — компонентные тесты; `pnpm lint` и `pnpm test` проходят.
- [ ] Документация (`CLAUDE.md`, `README.md` корня и приложений) обновлена под новые модуль, эндпоинты и env-переменные.
