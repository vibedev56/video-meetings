# PRD: Загрузка файлов встречи

**Дата**: 2026-11-17
**Статус**: Draft

## Цель

Владелец встречи может прикрепить к ней аудио- или видеозапись и сохранить её на сервере, чтобы потом скачать или передать на обработку. Файлы видны внутри карточки встречи в виде списка.

## Пользовательские сценарии

- Владелец открывает встречу и загружает аудио- или видеофайл -> файл сохраняется, появляется в списке файлов встречи со статусом «Загружен».
- Владелец выбирает файл, превышающий 500 МБ -> загрузка отклоняется с понятным сообщением, файл не сохраняется.
- Владелец загружает файл неподдерживаемого формата -> загрузка отклоняется с сообщением о допустимых форматах.
- Владелец загружает шестой файл к встрече, в которой уже 5 файлов -> загрузка отклоняется с сообщением о лимите.
- Владелец нажимает «Скачать» у файла -> браузер получает исходный файл с исходным именем.
- Владелец нажимает «Удалить» у файла и подтверждает действие -> файл исчезает из списка и удаляется с диска сервера.
- Пользователь, который не является владельцем встречи, не видит файлов этой встречи и не может их загрузить, скачать или удалить -> сервер возвращает 404, как для любой чужой встречи.
- Владелец открывает встречу без файлов -> видит пустое состояние с призывом загрузить файл.

## В скоупе

- Загрузка одного файла за раз через форму на странице встречи (выбор через диалог файлов или перетаскивание).
- Допустимые форматы:
  - аудио: mp3, wav, m4a, ogg;
  - видео: mp4, webm, mov.
- Проверка формата по расширению и по MIME-типу; отказ при несовпадении.
- Ограничения: максимум 500 МБ на файл, максимум 5 файлов на встречу.
- Прогресс загрузки в процентах и возможность отменить загрузку до завершения.
- Сохранение файла на локальной файловой системе сервера API. Метаданные (имя, размер, тип, дата загрузки, владелец встречи) сохраняются в PostgreSQL.
- Список файлов внутри страницы встречи: имя, размер, дата загрузки, кнопки «Скачать» и «Удалить».
- Скачивание файла через API с проверкой владельца.
- Удаление файла владельцем с подтверждением в интерфейсе; удаление файла с диска вместе с записью в БД.
- Сообщения об ошибках на русском языке для: неверного формата, превышения размера, превышения количества, обрыва сети, отказа сервера.
- API-эндпоинты для загрузки, списка, скачивания и удаления файлов встречи, все под JWT-авторизацией.

## Не в скоупе

- Обработка файлов: транскрибация, распознавание речи, суммаризация, AI-анализ. Статус «обработан» и связанные поля в этой итерации не вводятся.
- Доступ для участников встречи (поле `participants`) к файлам: просмотр, загрузка и скачивание только для владельца.
- Предпросмотр и проигрывание аудио или видео прямо на странице встречи.
- Загрузка файлов по ссылке (URL) и через сторонние хранилища (S3, облачные диски).
- Возобновляемая (resumable) загрузка после обрыва: при обрыве файл нужно загрузить заново.
- Редактирование файла (переименование, замена содержимого).
- Версионирование файлов.
- Антивирусная проверка содержимого.
- Шифрование файлов на диске.
- Квоты на общий объём файлов пользователя.
- Мобильная адаптация сверх базовой (интерфейс должен открываться на узком экране без горизонтальной прокрутки, но без специальной оптимизации).

## Технические ограничения

- Файлы хранятся на диске сервера API. Путь задаётся переменной окружения. Сервер должен иметь достаточно места: 5 файлов по 500 МБ на встречу означают до 2.5 ГБ на одну встречу.
- Раз файлы лежат на локальном диске, API в этой итерации работает как один экземпляр. Масштабирование на несколько инстансов требует общего хранилища и вынесено из скоупа.
- Лимит 500 МБ должен проверяться на сервере, а не только в браузере. Сервер должен отклонять запрос до полного приёма тела, если заявленный размер превышает лимит.
- Все эндпоинты работают с текущей JWT-авторизацией (`Authorization: Bearer <token>`). Доступ к файлу проверяется через владение встречей, как в существующих эндпоинтах `GET /meetings/:id`.
- Имена файлов из запроса не должны использоваться как путь на диске. Файлы на диске хранятся под сгенерированными именами; исходное имя хранится в БД и используется при скачивании.
- Схема БД меняется через Prisma-миграцию (новая таблица для файлов, связанная с `Meeting`, с каскадным удалением при удалении встречи). Файлы на диске при удалении встречи тоже должны удаляться, иначе они останутся «осиротевшими».
- Список допустимых форматов — предложение, которое нужно подтвердить перед реализацией.

## Критерии готовности

- [ ] Владелец загружает mp3, wav, m4a, ogg, mp4, webm и mov размером до 500 МБ; каждый файл появляется в списке встречи после загрузки.
- [ ] Файл больше 500 МБ отклоняется сервером с кодом 413; файл не появляется в списке и не остаётся на диске.
- [ ] Файл неподдерживаемого формата (например, txt или pdf) отклоняется с кодом 400; файл не сохраняется.
- [ ] Шестой файл к встрече с пятью файлами отклоняется с кодом 409; список остаётся прежним.
- [ ] Скачивание возвращает байты, идентичные загруженным (сравнение SHA-256), с исходным именем в заголовке `Content-Disposition`.
- [ ] Удаление файла убирает запись из БД и сам файл с диска; повторный запрос на скачивание возвращает 404.
- [ ] Удаление встречи удаляет все её файлы с диска и записи в БД.
- [ ] Пользователь, не являющийся владельцем, получает 404 на списке, загрузке, скачивании и удалении файлов чужой встречи.
- [ ] Запросы без токена или с невалидным токеном получают 401.
- [ ] В интерфейсе есть прогресс загрузки в процентах, кнопка отмены, пустое состояние и кнопки «Скачать» и «Удалить» у каждого файла.
- [ ] Удаление в интерфейсе требует подтверждения; без подтверждения файл не удаляется.
- [ ] Сообщения об ошибках (формат, размер, количество, сеть, сервер) отображаются на русском языке.
- [ ] Миграция Prisma применяется к чистой базе через `pnpm --filter api db:deploy` без ошибок.
- [ ] Юнит- или e2e-тесты покрывают: загрузку, отказ по размеру, отказ по формату, отказ по количеству, скачивание, удаление и проверку владельца.
- [ ] `pnpm lint` и `pnpm test` проходят для `apps/api` и `apps/web` без ошибок.
- [ ] Изменение проверено визуально в браузере: скриншоты страницы встречи в пустом состоянии, во время загрузки и со списком файлов сохранены в папку `screenshots/`.
