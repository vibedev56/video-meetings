# Plan: Загрузка файлов встречи

**PRD:** d:\Repositories\pet projects\video-meetings\docs\prd-meeting-file-upload.md
**Дата:** 2026-11-17

## Решения, принятые до начала работ

- В скоуп добавлен `DELETE /meetings/:id` (owner-only), иначе критерий «удаление встречи удаляет файлы с диска» нельзя проверить. Публичного UI удаления встречи в этой итерации нет.
- В `apps/web` добавляется тестовая инфраструктура (Vitest + Testing Library, скрипт `test`). Каждая фаза содержит тесты своего функционала, включая фазы frontend.
- Список форматов подтверждён: аудио mp3, wav, m4a, ogg; видео mp4, webm, mov.

## Фазы реализации

### Фаза 1: Схема, загрузка и список файлов (Tracer Bullet)

**Цель:** Владелец может загрузить файл через API и получить список файлов встречи. Все проверки на стороне сервера (формат, размер, количество, владелец) работают end-to-end.
**Затрагивает:** database, backend
**Задачи:**

- [ ] Prisma-модель `MeetingFile` (id, `meetingId` с `onDelete: Cascade`, `originalName`, `storedName`, `sizeBytes`, `mimeType`, `uploadedAt`) и миграция через `pnpm --filter api db:migrate`.
- [ ] Переменная окружения для каталога файлов (например, `MEETING_FILES_DIR`), чтение в конфиге, запись в `.env.example`.
- [ ] `POST /meetings/:id/files`: проверка владельца (404 для чужой встречи), отказ 413 по `Content-Length` до приёма тела и лимит 500 МБ при потоковом приёме, проверка расширения и MIME по белому списку (400), лимит 5 файлов (409). Файл сохраняется под сгенерированным именем, при любой ошибке временный файл удаляется.
- [ ] `GET /meetings/:id/files`: список файлов с проверкой владельца (404) и JWT (401).
- [ ] **Тесты фазы:** unit-тесты функции валидации (расширение + MIME по паре, граница 500 МБ, граница 5 файлов). E2E-тесты в `apps/api/test/`: загрузка mp3 и mov, 413, 400, 409, 404 для чужой встречи, 401 без токена и с невалидным токеном. Проверяется, что после отказов на диске ничего не остаётся.

**Когда готова:** `pnpm --filter api test` и `pnpm --filter api test:e2e` проходят; загрузка mp3 и mov возвращает запись в списке; при 413, 400 и 409 список не меняется и файлов на диске нет; `db:deploy` применяет миграцию на чистой базе.

### Фаза 2: Скачивание, удаление файла и удаление встречи

**Цель:** Файлы можно скачать и удалить. Удаление встречи очищает её файлы на диске.
**Затрагивает:** backend
**Задачи:**

- [ ] `GET /meetings/:id/files/:fileId`: потоковая отдача файла, заголовок `Content-Disposition` с исходным именем (корректно для кириллицы, через `filename*`), 404 для чужой встречи или отсутствующего файла.
- [ ] `DELETE /meetings/:id/files/:fileId`: удаление записи в БД и файла с диска, 404 для чужой встречи.
- [ ] `DELETE /meetings/:id` (owner-only, 404 для чужой встречи): перед удалением записи читается список файлов, после удаления встречи (каскад в БД) файлы удаляются с диска.
- [ ] **Тесты фазы:** unit-тесты сервиса очистки файлов (удаление по списку, устойчивость к уже отсутствующему файлу на диске). E2E-тесты: скачивание с совпадением SHA-256 и правильным `Content-Disposition`; удаление файла убирает файл с диска, повторное скачивание даёт 404; удаление встречи удаляет её файлы с диска; 404 для чужой встречи на скачивании и удалении.

**Когда готова:** `pnpm --filter api test` и `pnpm --filter api test:e2e` проходят; SHA-256 скачанного файла совпадает с загруженным; после `DELETE` файла нет ни в БД, ни на диске; после `DELETE` встречи её файлы отсутствуют на диске.

### Фаза 3: Интерфейс списка файлов: скачивание и удаление

**Цель:** На странице встречи владелец видит файлы, скачивает их и удаляет с подтверждением.
**Затрагивает:** frontend
**Задачи:**

- [ ] Методы в `apps/web/src/lib/api.ts`: получить список, скачать (запрос с `Authorization: Bearer`, сохранение blob с именем из `Content-Disposition`), удалить файл.
- [ ] Блок «Файлы» на странице встречи: имя, размер, дата загрузки; пустое состояние с призывом загрузить файл.
- [ ] Кнопка «Скачать» у каждого файла с сообщением об ошибке на русском при обрыве сети или отказе сервера.
- [ ] Кнопка «Удалить» с модальным подтверждением (HeroUI Modal). Без подтверждения запрос на удаление не отправляется.
- [ ] **Тесты фазы:** настройка Vitest + Testing Library и скрипта `test` в `apps/web`. Тесты: методы API-клиента (с замоканным `fetch`, включая заголовок Bearer и обработку ошибок сети); список и пустое состояние; сообщение об ошибке при скачивании; удаление не отправляет запрос без подтверждения, а после подтверждения убирает файл из списка; отмена в модальном окне ничего не удаляет.

**Когда готова:** `pnpm --filter web test`, `lint` и `build` проходят; владелец видит список и пустое состояние; скачанный файл совпадает с исходным; после подтверждения файл пропадает из списка.

### Фаза 4: Интерфейс загрузки

**Цель:** Владелец загружает файл через форму с прогрессом, может отменить загрузку и видит понятные ошибки на русском.
**Затрагивает:** frontend
**Задачи:**

- [ ] Форма загрузки на странице встречи: выбор через диалог файлов или перетаскивание, один файл за раз, предварительная проверка формата и размера в браузере (сервер остаётся основной проверкой).
- [ ] Загрузка через `XMLHttpRequest` с прогрессом в процентах и отменой (`xhr.abort()`). После успеха список обновляется; после отмены список остаётся прежним.
- [ ] Сопоставление ошибок с русскими сообщениями: неверный формат (400), превышение размера (413), лимит файлов (409), обрыв сети, отказ сервера (5xx).
- [ ] **Тесты фазы:** unit-тесты предварительной проверки формата и размера и сопоставления ошибок. Тесты компонентов с замоканным `XMLHttpRequest`: отображение прогресса в процентах, отмена прерывает загрузку и не добавляет файл, успех обновляет список, каждая ошибка показывает русское сообщение.
- [ ] Визуальная проверка в браузере: скриншоты пустого состояния, процесса загрузки и списка с файлами сохранены в `screenshots/`.

**Когда готова:** `pnpm --filter web test`, `lint` и `build` проходят; все семь форматов загружаются через UI и появляются в списке; отмена прерывает загрузку и не добавляет файл; ошибки формата, размера, количества и сети показываются на русском; скриншоты лежат в `screenshots/`.

## Замечания по реализации

- MIME-типы для m4a, ogg и mov различаются у браузеров и ОС (например, `audio/x-m4a`, `audio/mp4`, `video/quicktime`). Белый список нужно держать по паре «расширение → допустимые MIME», а не только по одному значению.
- Лимит 500 МБ применяется дважды: по `Content-Length` до приёма тела и по фактическому размеру при потоковом приёме (multipart добавляет накладные расходы, поэтому проверка по заголовку должна учитывать запас).
- Каталог файлов создаётся при старте, если его нет. При запуске в нескольких инстансах хранение на диске не работает, это вынесено из скоупа PRD.
