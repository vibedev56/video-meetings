# Plan: Профиль пользователя и его редактирование

**PRD:** docs/prd-user-profile-editing.md
**Дата:** 2026-11-18

## Фазы реализации

### Фаза 1: Профиль и имя (backend, tracer bullet)

**Цель:** Сквозной минимальный путь через БД и API: пользователь получает свой профиль и меняет имя.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Миграция Prisma: необязательное поле имени у `User`.
- [ ] Эндпоинт получения профиля текущего пользователя (email, имя, признак наличия аватара) только для авторизованных.
- [ ] Эндпоинт изменения имени текущего пользователя; пустое имя сбрасывает значение; нельзя менять чужой профиль.
- [ ] Unit- и e2e-тесты: получение профиля, смена и сброс имени, 401 без токена, изоляция между пользователями.
- [ ] Обновить `apps/api/CLAUDE.md` и `apps/api/README.md` (модуль профиля, эндпоинты).

**Когда готова:** e2e-тесты проходят; `pnpm --filter api lint`, `test` и `test:e2e` зелёные; имя сохраняется и возвращается профилем.

### Фаза 2: Страницы профиля и редактирования имени (frontend)

**Цель:** Пользователь видит профиль и меняет имя в интерфейсе; имя отображается в шапке.
**Затрагивает:** frontend
**Задачи:**

- [ ] Страница профиля: имя (или email, если имя пусто), email, инициалы вместо аватара; редирект на вход для неавторизованных.
- [ ] Страница редактирования с формой смены имени, сообщениями об успехе и ошибке; ссылка на профиль из шапки.
- [ ] Показ имени (или email) в блоке «кто залогинен» в шапке главной; обновляется после сохранения без повторного входа.
- [ ] Компонентные тесты страниц, формы и шапки.
- [ ] Обновить `apps/web/CLAUDE.md` и `apps/web/README.md` (новые маршруты).

**Когда готова:** `pnpm --filter web lint` и `test` зелёные; изменённое имя видно в профиле и шапке без перелогина.

### Фаза 3: Смена пароля (backend)

**Цель:** API меняет пароль по старому паролю.
**Затрагивает:** backend
**Задачи:**

- [ ] Эндпоинт смены пароля: проверка старого пароля, ошибка при неверном.
- [ ] Валидация нового пароля: минимум 8 символов, не совпадает со старым; текущие токены остаются действительными.
- [ ] Unit-тесты (хеш, проверка старого, совпадение со старым).
- [ ] e2e-тесты: успех, неверный старый, короткий новый, совпадающий новый; вход со старым паролем отклоняется, с новым проходит; сессия остаётся рабочей; 401 без токена.
- [ ] Обновить `apps/api/CLAUDE.md` и `apps/api/README.md`.

**Когда готова:** e2e-тесты проходят, `pnpm --filter api lint`, `test`, `test:e2e` зелёные.

### Фаза 4: Форма смены пароля (frontend)

**Цель:** Пользователь меняет пароль на странице редактирования.
**Затрагивает:** frontend
**Задачи:**

- [ ] Форма смены пароля (старый и новый пароль) на странице редактирования.
- [ ] Клиентская проверка длины нового пароля и понятные сообщения об ошибках сервера (неверный старый, совпадающий со старым).
- [ ] Сообщение об успехе; пользователь остаётся на странице залогиненным.
- [ ] Компонентные тесты формы (успех, каждая ошибка).
- [ ] Обновить `apps/web/CLAUDE.md`.

**Когда готова:** `pnpm --filter web lint` и `test` зелёные; пароль меняется через интерфейс, сессия сохраняется.

### Фаза 5: Аватар (backend)

**Цель:** API принимает, отдаёт, заменяет и удаляет аватар.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Миграция Prisma: ссылка на файл аватара у `User`; директория хранения и env-переменная (по аналогии с `MEETING_FILES_DIR`).
- [ ] Эндпоинт загрузки: проверка формата (JPG/PNG/WebP) и размера (до 2 МБ) на сервере до записи на диск; при замене старый файл удаляется.
- [ ] Эндпоинт получения файла аватара для залогиненных и эндпоинт удаления (файл удаляется с диска).
- [ ] Unit- и e2e-тесты: допустимые форматы, отказ по формату и размеру (текущий аватар не меняется), замена и удаление чистят диск, 401 без токена, изоляция пользователей.
- [ ] Обновить `apps/api/CLAUDE.md`, `apps/api/README.md`, `.env.example` и корневые доки при необходимости.

**Когда готова:** e2e-тесты проходят, `pnpm --filter api lint`, `test`, `test:e2e` зелёные.

### Фаза 6: Аватар в интерфейсе (frontend)

**Цель:** Пользователь загружает, меняет и удаляет аватар; он виден в профиле и шапке.
**Затрагивает:** frontend
**Задачи:**

- [ ] Блок загрузки аватара на странице редактирования: выбор файла, клиентская проверка формата и размера, сообщения об ошибках сервера.
- [ ] Удаление аватара; после него показываются инициалы.
- [ ] Показ аватара (или инициалов) на странице профиля и в шапке главной; обновление без повторного входа.
- [ ] Компонентные тесты: загрузка, отклонение файла, удаление, отображение в профиле и шапке.
- [ ] Обновить `apps/web/CLAUDE.md`, `apps/web/README.md`, корневые `CLAUDE.md` и `README.md`; прогнать `pnpm lint` и `pnpm test`.

**Когда готова:** `pnpm lint` и `pnpm test` зелёные; аватар загружается, заменяется, удаляется и виден в профиле и шапке; документация соответствует коду.
